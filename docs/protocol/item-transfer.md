# T133 刪除與給予物品

Issue #273；2026-11-07。依據 `docs/reference/server-protocol.md`、`server-rules.md` R11、R26，另唯讀核對目前伺服器處理器。未讀配置、資料表或 DB，未複製伺服器程式碼。

## 封包與回包

| 封包 | opcode 後的欄位 | 引擎行為 |
|---|---|---|
| C138 `C_DeleteInventoryItem` | D 物品實例 ID | **整疊刪除**，沒有數量欄位；顯示名稱／整疊數量，預設「否」的本地確認後才送 |
| C45 `C_GiveItem` | D 目標 ID、H x、H y、D 物品實例 ID、D 數量 | 使用放下時的目標座標；數量 1…持有量，上限 `int.MaxValue` |
| S57 `S_DeleteInventoryItem` | D 物品實例 ID | 沿用既有背包移除處理 |
| S24 `S_ItemAmount`／`S_ItemStatus` | D ID、S 名稱、D 數量、C 狀態長度、狀態 bytes | 沿用既有背包數量／狀態處理 |
| S71 `S_ServerMessage` | H 訊息 ID、C 參數個數、各參數 S | 沿用原服訊息顯示，不能視為成功回覆 |

D/H 為 little endian。C138 原始欄位共 5 bytes，補零至 8；C45 共 17 bytes，補零至 24，沿用傳輸層的 8-byte 對齊。送出請求不自行刪除物品或扣數量。

## UI 與狀態生命週期

原生「更多 → 背包」新增垃圾桶按鈕與拖入區。背包列表拖到可見場景物件像素，送 C45；拖到垃圾桶，確認後送 C138；拖到空地／介面外或按 Esc 不送出。場景命中沿用原有遮擋與像素命中檢查，不新增座標猜測。

現有原生數量介面是背包文字欄位（`dropCount`），並無獨立原生數量對話。給予沿用此欄位及 `GroundCatalog.TryCount`，先輸入數量再拖放；確認視窗再次顯示物品、數量與目標，可取消回欄位修改。刪除忽略此欄位並明示整疊。Web 背包與 HUD 快捷欄未新增拖放入口。

拖曳開始保存物品實例、背包數量／選取 revision、連線／世界世代及自身位置／裝備狀態；放下時保存目標實例。確認後及傳輸鎖內再次驗證，目標移除重建、位置改變、背包回包、換選、死亡、傳送鎖定等均使請求失效。確認請求只能使用一次。使用既有 item busy／lease 與 900ms 點擊保護，無自動追蹤、重送或背包預扣。
