# T142 能力值重置契約

Issue #359。唯讀核對 `docs/reference/server-protocol.md`、`server-rules.md` 與本機 Java；不收錄伺服器原始碼，未連伺服器或 DB。

## 封包與階段

能力順序均為 STR、INT、WIS、DEX、CON、CHA。C/H 分別為 1/2 byte，H 為 little endian；傳輸依既有 LoginPackets 補零至 8-byte 邊界。

| 方向 | 欄位 | 語義 |
|---|---|---|
| C98 | C(1), 六個 C(能力值) | 出生配點；原服立即修改出生能力並排程保存，回 S64/2、等級 1 |
| C98 | C(2), C(0) | 提升 1 級、不加能力 |
| C98 | C(2), C(1..6) | 對應能力 +1，提升 1 級 |
| C98 | C(2), C(7) | 提升 10 級；伺服器拒絕剩餘等級不足 10 |
| C98 | C(2), C(8), C(0..6) | 完成；尾碼 1..6 先加一點，0 不加。若有萬能藥點數回 S64/3，否則保存 |
| C98 | C(3), 六個 C(能力值) | 萬能藥分配後的絕對能力值，保存並傳送 |
| S64/1 | H(初始 HP), H(初始 MP), C(10), C(最大等級) | 開始重置；HP/MP 不是職業 ID，精靈、龍騎士、幻術師皆為 15/4 |
| S64/2 | C(等級), C(最大等級), H(HP), H(MP), H(有號 AC), 六個 C(能力值) | 原服逐步計算結果，完整語義長度 16 bytes |
| S64/3 | C(點數) | 萬能藥剩餘點數，語義長度 3 bytes |
| S64/4 | C(INT高半位元組/STR低), C(DEX高/WIS低), C(CHA高/CON低), C(0), H(0) | 出生額外能力資訊，非重置授權；完整長度 8 bytes |

S64/1 的七職業 HP/MP 為 14/2、16/1、15/4、12/6、12/3、15/4、15/4。職業從本次選角清單與當前角色名取得，不用 HP/MP 猜測。S64/0x3c 是盟徽，S64/0x2a 是書籤；本模組不接管，其他子型也保持原有分派。本次基底尚無書籤 case，只加入一個 `case 64 when subtype is 1..4`。

## 規則與本機保護

- 出生能力依 `C_CreateChar` 七職業下限與總和 75；`CharacterManagementPackets.BaseStats` 提供同一張表。C98 本身未完整驗證配點，本機不得照其寬鬆處理器送任意數值。
- 本機在升至 51 級起逐級分配一點；10 級提升不得跨過 50 級。達最大等級後送 `C98,2,8,0`，因能力已在升級時配完，完成不得再加一點。上限 35 為本機保守政策，與既有能力點上限一致，並非宣稱 C98 handler 自己檢查 35。
- 萬能藥只能在原服 S64/3 指定點數內增加，不能降低既有能力。每次確認只送一次；不樂觀增加 HP、MP 或能力。
- 每次送出攜帶連線世代、世界 epoch、角色 ID、修訂與職業快照，sender gate 再核對。等候 S64/2 時核對預期等級、最大等級與六能力，重複／不相符回包不解鎖下一步。15 秒逾時結果標示未知，不自動重送，也不讓遲到回包重新開放操作。
- 原生 NPC `ent` 先檢查回憶蠟燭 49142、卸裝，開始傳送至 997，再設定暫時等級與送 S64/1。本機允許尚未送出的出生配點視窗隨同一角色狀態實例的傳送到達更新 epoch；舊按鈕快照仍失效。C98 已送出後，換圖會退役整個流程。重登入即使同一 ID 也不沿用舊視窗。
- 重置送出允許原服凍結狀態，但仍拒絕死亡、傳送中、交易與其他動作忙碌。UI 是主視窗持有的 modal WinForms 視窗；接收工作持續運行，關閉時提示中斷連線，沒有捏造取消封包。
- 保存方法發 S8、解凍並傳送。本機不以普通能力／血量更新當保存成功回覆；等待換圖退休視窗。DB 保存、道具扣除與重新登入後的結果仍須真機核對。
