## 已驗證

1. A、A2 的 `window-events.json` 均記錄 `native-ui: verifying → failed`，沒有 `active`。A 日誌第一行至 fallback 為約 3.763 秒；A2 程序啟動至 fallback 約 5.736 秒。這不是「視窗出現至接手」耗時，因從未接手，也沒有足夠證據評定啟動效能。
2. 畫面實際顯示「原客戶端 UI 資源與鎖定版本不符」，詳細錯誤卻是 `uimagicitem.xml:SPELL_WINDOW: 魔法清單沒有空間（等級鈕／箭頭的位置不合理）`。呼叫鏈：`SpellWindowPanel.cs:123` → `ItemWindowPanel.cs:94` → `UiRoot.cs:232` → `UiClientBridge.cs:31`。目前顯示訊息沒有區分版面例外與資源 pin 失敗。
3. 使用同一產品 DLL 的唯讀診斷程式載入真實 XML／surf，重現同一例外：等級鈕圖例如 2058c.img 為 **14×212**、位置 (12,37)；上／下箭頭為 (171,44)／(171,225)。`stripBottom=37+212=249`，清單 top=249、bottom=225，故 `Rows.PageSize=0`。62 個註冊面板逐一呼叫 Load，只有 SPELL_WINDOW 拋例外；其餘「沒拋例外」不代表面板已啟用、外觀或互動通過。
4. `--classic-ui` 與設定檔關閉皆不產生 native-ui 啟動事件，舊介面可顯示；可存取性樹顯示自動出現「登入／選角」分頁且帳號框有焦點。移除測試設定後 A-restored 重新驗證原生 UI，仍被相同例外拒絕；產品預設未更改。
5. 外部 Windows Graphics Capture 兩次逾時，改用客戶端既有 `Ctrl+Shift+F12` 取證；`manual-client.png` 是執行中視窗的 DrawToBitmap，A 的 `manual-screen.png` 另有實際 CopyFromScreen 證據。沒有合成遊戲狀態。原生畫布未成立，所以不能把 `manual-logical.png` 的離線場景當作 native UI 邏輯畫布。
