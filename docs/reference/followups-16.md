# 查證補遺第 16 輪（FU16）：頭上對話框版面（Q9-1，T414／#956）

依據：[`gap-matrix.md`](gap-matrix.md) 15.13.6 的 Q9-1 與 R11-E（T412／#952，PR #954）；#916 報告（`docs/reports/issue-916.md`）第 25–26、36、40、72–73 行。

記號：**已驗證**＝反編譯、反組譯或資源檔直接看到；**推測**＝依欄位、命名或旁證判斷；**待驗證**＝本輪查不到，寫明卡在哪裡。

**結論**
- 頭上對話框**不用任何 surf 或圖檔**。框、圓角、尾巴都是程式內建的 1 bpp 小點陣（`.data` 52 bytes），再加 1 px 線段，全部用同一個顏色畫（§3）。PakViewer 查過全部 24 個 idx，也沒有對話框相關的資源（§0.4）。
- 任務標題寫的 `sub_7D07C0` **不是繪製函式**，是「矩形聯集」（用來累計要重畫的範圍）。真正的繪製是 `sub_7CF290`，每幀由主繪製 `sub_F0F0C0` 呼叫（§3）。
- 「全名模式 −32」要更正：條件是**「全部顯示名稱」打開，而且物件的 +252 字串不是空的**。只開全名模式不算（§2.1）。
- 斷行**不是固定 16／20 字**。16／20 是目標寬度，一行最多可以到目標寬度的 1.5 倍（商店訊息 1.25 倍）；剩下的字在這個範圍內放得下，就整段放在最後一行（§1.3）。
- 「泡泡話框」選項（`byte_13AAF28`，option12 `#1003`）關閉時**仍然會畫**對話框，只是不畫外框（文字加一個實心小三角）。商店訊息（`a4`＝5）一律有外框（§1.1、§3.2）。

## 1. 文字處理（`sub_7CE710` → `sub_7D01E0`）

### 1.1 建立前的條件與前處理（已驗證）

依呼叫順序：

1. `byte_13CE518` 打開，而且文字裡有 >0x7F 的位元組 → 不畫。
2. `sub_A4A230(Key)` 找不到物件 → 不畫。
3. 移除這個物件原有的對話框（`sub_A44900`，物件 +408 存著目前的對話框）。**每個物件最多一個**；舊的在這一步就移除，即使後面的條件讓新的不畫。
4. 關鍵字過濾 `sub_4FED10(文字)`：回 2＝沒設過濾、1＝符合、0＝沒符合。回 0 時，`a4`＝−1 改成 5；`a4`＝5 就不畫；其他情況照畫。
5. 建物件（0x3A4 bytes）：+920＝物件、+926＝`a5`、+928＝`a7`；並把物件 +408 設成這個對話框。
6. `sub_7CE6B0`：文字最後一個字元是空白時，往前找到第一個不是空白的字元；如果是 `:`，就從那裡截斷（例如 `"名字: "` 變成 `"名字"`）。最後一個字元不是空白就不處理。
7. `sub_7CF080`：最多複製 768 bytes 到對話框 +0。
   - 去掉 `\f?`、`\b?`（第三個字元 ≥ `'0'`）與 `\i0`–`\i5`，每個 3 bytes。
   - 其他 `\` 序列保留（包括 `\j`、`\c`，交給畫字函式處理）。
   - 字型存到 +868：預設 `h`；CodePage 932 用 `ho`、950 用 `dword_13CD54C`、936 用 `dword_13CD550`。
8. 顏色是 palette[14] 時（`sub_7CFE90`）：把 10 個 Big5 字各換成兩個空白。
   - 這 10 個字：`〤 ﹥ ﹤ 〦 〩 十 〧 〨 〡 〥`（`A2C6 A1E1 A1E0 A2C8 A2CB A2CC A2C9 A2CA A2C3 A2C7`）。
   - 字表在 `Buf2`＝`0x1368D20`，指向 `.rdata` `0x1172F80`–`0x1172FA4`（FO `0xD71B80`）。
   - 判斷用 `IsDBCSLeadByteEx(dword_13CE508)`。
9. 目標寬度 `W0`＝`byte_13AAF28 ? 16 : 20`（bytes）。呼叫 `sub_7D01E0(文字, 長度, +770, &W0, 1, a5)` 取得行數 `n`（+873）；`W0` 被改寫成最長一行的 byte 數 `w`。

### 1.2 斷點代價表（`sub_7D01E0` 第一段，已驗證）

對每個位置 j 給一個代價，代表「在 j 後面斷行」（下一行從 j+1 開始）的優先程度。代價越低越優先。c＝第 j 個 byte，nx＝第 j+1 個 byte。

| 情況 | 代價 |
|---|---|
| c 是雙位元組字的第一個 byte（只看最高位元，兩個 byte 一組） | 999（不能斷） |
| `\f` 加上有效色碼（`sub_844810`，色碼表 `byte_136AB30` 16 個加 `byte_136AB1E`）的 3 個 byte | 999；另外記一筆色碼，算寬度時扣 3 |
| c＝`\n`，而且 nx＝0 | −999 |
| c 是空白或 Tab：nx 也是空白或 Tab | 1 |
| 　　　　　　　　 nx＝`\n` | −99 |
| 　　　　　　　　 其他 | 0 |
| c 是雙位元組字的第二個 byte：nx 最高位元是 1 | 2 |
| 　　　　　　　　　　　　　　 nx＝`\n` | −99 |
| 　　　　　　　　　　　　　　 其他 | 3 |
| c 是其他字元：nx＝`\n` | −99 |
| 　　　　　　　 nx 是空白或 Tab | 3 |
| 　　　　　　　 nx 不是 0 | 4 |
| 　　　　　　　 nx＝0 | 0 |

說明：
- `\n` 本身沒有特別處理，它前面那個字元的代價是 −99。
- 本來就不會遇到 `\f`，因為 §1.1 第 7 步已經去掉了。

### 1.3 斷行（`sub_7D01E0` 第二段，已驗證）

- 每行最多 `M` bytes，`M`＝`W0 + W0/2`；商店訊息（`a6`＝`a5`＝1）是 `W0 + W0/4`。另外加上色碼的 byte 數（實際上是 0）。

  | | 泡泡話框 關（W0＝20） | 泡泡話框 開（W0＝16） |
  |---|---|---|
  | 一般聊天 | 30 | 24 |
  | 商店訊息 | 25 | 20 |

- 演算法（start＝目前這一行的開頭）：
  1. 記下 start 是一行的開頭。
  2. 掃描 j，從 start 到 `min(start+M, len)` 之前：
     - 代價比目前最佳值低 → 最佳斷點改成 j+1（最佳值一開始是 99）。
     - 代價和最佳值相同、不是 −99，而且 j+1 比較靠近字串結尾 → 改成 j+1。也就是**同代價取最後一個**；比較的對象是第一段迴圈留下的 `i`（約等於 `len`，`0x7D0623` 與 `0x7D0643` 讀的是同一個 `var_1808`）。
     - 第二次遇到 −99 → 立刻停止掃描，用第一個 −99。
  3. 掃到 `len`（剩下的字在 M 之內放得下）→ **剩下的整段就是最後一行**，第 2 步找到的斷點不用。否則 start＝最佳斷點，回到第 1 步。
- 輸出：
  - 每行開頭存在 +770 起的 `short[]`，最後一個元素是 `len`。
  - 行數 `n` 存在 +873（char）。
  - `w`＝最長一行的 byte 數，每個色碼扣 3。
- 邊界：`len`＝0 時 `n`＝0，框會變成只剩邊（推測；呼叫者都會給非空字串）。

## 2. 位置（`sub_7CE710`、`sub_7CE370`）

### 2.1 錨點（已驗證）

- P＝`sub_F1A750(物件 +16 的格座標)`，就是物件格子的螢幕點，與名稱、頭上條用的 P 相同。
- 物件外框 R＝P＋外框表，外框表是 `*(物件+56)` 的第 `*(char*)(物件+52)` 筆，每筆 24 bytes，從第 +16 個 byte 開始是 left／top／right／bottom（`sub_A3E850`）。下面的 R.Top／R.Bottom 就是 actions-and-names.md §2.3 的 T 與外框下緣。
- 錨點 A（+892／+896，也就是任務寫的 dword +223／+224）：
  - `A.x = P.x + 24`
  - `A.y = R.Top − k − m`
    - `k`＝17：自己（`Key == dword_15442C8`），而且 showCharacterHPMP（`byte_138BE7C`）打開（避開頭上條）。
    - `k`＝32：上一條不成立，而且「全部顯示名稱」（`byte_138BE7F`）打開、**物件 +252 字串不是空的**（`sub_A41EC0` → `sub_A0C4F0(+252)`＝0）。
    - `k`＝12：其他情況。
    - `m`：物件 +608 不是空的時，用它的虛擬函式 +292 的回傳值；否則 0。推測是坐騎或附加物件的高度，本輪沒有追。
- 錨點只在建立時算一次，對話框**不會跟著說話的人移動**。只有 `sub_7CFF40` 會把全部對話框一起平移，然後重新夾邊界。它的呼叫者是 `sub_A4C270`（自己走路的後續步，FU14§0.3）與 `sub_915330`。推測是鏡頭捲動時用。

### 2.2 框的矩形與夾邊界（已驗證）

框的矩形相對於 A（+876 起是 left／top／right／bottom，bottom 一律 0）：

| | left | top | right | 外框 +872 |
|---|---|---|---|---|
| 有外框（`泡泡話框` ∨ `a4`＝5 ∨ `a6`） | `−3w − 5` | `−12n − 14` | `3w + 5` | 1 |
| 沒有外框 | `−3w` | `−12n − 6` | `3w` | 0 |

- 螢幕上的矩形 B＝A＋上表（+900 起）。
- 尾巴相對於左緣的位移 `t`（+916）一開始是 `−left`，也就是 `3w+5` 或 `3w`。

`sub_7CE370` 夾邊界（座標系和 `sub_A3ED50` 名稱框相同，左右界 48／880；反組譯 `0x7CE3BF`–`0x7CE522` 核對過常數）：

1. `B.L < 48`：`d = 2 − B.L`（照原碼，`0x7CE3CB mov edx,2`），整個框右移 d，`t −= d`；`t < 8` → 不畫。
2. 否則 `B.R > 880`：`d = 880 − B.R`，整個框平移 d，`t −= d`；`t > (B.R − B.L) − 9` → 不畫。
3. `B.T < 48`：整個框下移 `R.Bottom − B.T`，框的上緣移到物件外框的下緣；尾巴改成朝上（+874＝4）。否則 +874＝0。
4. 最後必須 `B.T ≥ 48` 而且 `B.B ≤ 540`，否則不畫（不畫時直接刪掉這個對話框）。

### 2.3 另一個入口 `sub_7CEC40`（已驗證，給 R11-E 參考）

- 呼叫者是 `sub_915330` 與 `sub_E51C60`。`sub_E51C60` 先組成 `"%s : %s"` 的格式；它把 `a4` 限制在 1–8（超出範圍改成 8），顏色限制在 1–95（超出範圍改成 palette[14]）。
- 和 `sub_7CE710` 的差別只有兩點：`A.y = R.Top − 2`（沒有 k／m），以及不設 +928 圖示。其他（斷行、外框、夾邊界、計時、重疊變灰）都相同。

## 3. 繪製（`sub_7CF290`，已驗證）

### 3.1 流程

- 每幀由 `sub_F0F0C0` 呼叫，參數是重畫範圍。
- 依串列順序畫（舊的先畫，新的蓋在上面）。只畫和重畫範圍相交的框（`sub_7CF230`，嚴格相交）。
- `byte_13CE518` 打開而且文字裡有 >0x7F 的位元組時跳過。

變數：c＝+924 的顏色；L、T、R、Bm＝+900 的矩形；t＝+916；f＝+872；u＝+874（4 表示尾巴朝上）。

### 3.2 外框與尾巴

點陣的格式（`sub_97B150(面, bits, x, y, 寬, 高, 色)`）：每列 `ceil(寬/8)` bytes，最高位元在最左邊，位元為 1 的點用該色畫，位元為 0 的點不畫。

**有外框（f＝1）**

| | 尾巴朝下（u＝0） | 尾巴朝上（u＝4） |
|---|---|---|
| 尾巴 | `TF` 7×4 畫在 `(L+t−3, Bm−4)` | `TF↑` 7×4 畫在 `(L+t−3, T)` |
| 上邊 y＝top | `T` | `T+4` |
| 下邊 y＝bot | `Bm−4` | `Bm−1` |
| 有缺口的那條邊 | 下邊 | 上邊 |

- 框色 c′：`sub_4FED10(文字)`＝1（符合關鍵字）時用 palette[2]（綠），否則用 c。
- 直線：`(L, top+5, 1, bot−top−9)` 與 `(R−1, top+5, 1, bot−top−9)`。
- 有缺口的邊：`(L+5, y, t−8, 1)` 與 `(L+t+4, y, R−L−t−9, 1)`。
- 完整的邊：`(L+5, y, R−L−10, 1)`。
- 四個 4×4 圓角：`TL (L+1, top+1)`、`TR (R−5, top+1)`、`BL (L+1, bot−4)`、`BR (R−5, bot−4)`。
- 尾巴本身用 c 畫，不是 c′。
- 線段和圓角的端點是斜向相鄰（8 連通），所以看起來是圓角。
- 框裡面**不填底色**，只有框線。

**沒有外框（f＝0）**：只畫實心三角形，沒有框線。

| | 尾巴朝下 | 尾巴朝上 |
|---|---|---|
| 黑邊三角 9×5（palette[0]） | `TO` 畫在 `(L+t−3, Bm−5)` | `TO↑` 畫在 `(L+t−3, T)` |
| 色三角 7×4（c） | `TC` 畫在 `(L+t−3, Bm−4)` | `TC↑` 畫在 `(L+t−3, T+1)` |

兩個三角形的 x 都是 `L+t−3`（反組譯 `0x7CF47A`、`0x7CF4B1`），所以色三角的尖端比黑邊三角**偏左 1 px**。這是原版的樣子，照做即可。

### 3.3 文字

- 起點：有外框時是 `(L+5, top+5)`；沒有外框時尾巴朝下是 `(L, T)`、朝上是 `(L, T+6)`。
- 第 k 行（k 從 0 開始）的 y 是起點的 y＋`12k`。內容是 +0 文字的 `[start[k], start[k+1])`。
- 畫字用 `sub_841770(面, 字串, 長度, x, y, c, palette[0], k>0)`：
  - 第 k≥1 行沿用上一行最後的顏色（只影響 `\f`／`\a` 色碼；`\f` 已經去掉，`\a?` 會留下來）。
  - 點陣字型的路徑（`sub_83E100`，沒有 GDI 字型 `h` 時）：
    - ASCII：6×12 的字用 c 畫，8×14 的黑框字畫在 (x−1, y−1)，每個字 x＋6。
    - Big5：12×12 的字加 14×14 的黑框字，每個字 x＋12。
    - 也就是 **1 px 黑框、行高 12、每個 byte 6 px**。
  - 有 GDI 字型時改走 `sub_83E490`，參數相同。本輪沒有追。

### 3.4 圖示（+928＝`a7` > 0）

## 4. 生命週期（已驗證）

- **計時**：建立時排 `1000·a4` ms 後執行 `sub_7CFE50`，從串列移除並清掉物件 +408。一般聊天 8 秒，商店訊息 5 秒。
- **重疊變灰**：新框建立而且通過夾邊界後，**其他**和它相交的框，顏色改成 palette[23]（`0x4A52`，灰）。已經是灰色的不再處理；新框本身維持原色。
- **商店訊息**（#916）：
  - `sub_7CFFC0` 每 5000 ms 切換兩行。
  - 只有 `byte_136E99F`（個人商店名稱）打開時才畫，`a5`＝1。
  - `sub_7CFCB0(物件)` 會移除該物件 `a5`＝1 的框。
  - 商店框一律有外框（`a4`＝5）。
