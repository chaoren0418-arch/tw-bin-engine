## 1. 本地施法動作（T100、T113–T119）

### 1.1 已驗證：送出 C6 時不在本地播放任何動作

TW16 的技能物件是 `LineageSpell::CSpell` 家族（RTTI，`rtti.py`）。vtable 第 3 格是「施放」，全部只送封包：

| 類別 | 施放函式 VA／FO | 送出 | 備註 |
|---|---|---|---|
| `CSpell`（一般） | `0xDF8A50`／`0x9F7E50` | `ccc`；技能 50 送 `cccd`（值 7–13） | |
| `CSpellTarget` | `0xE2A9C0`／`0xA29DC0` | `cccd`（目標 id） | 沒有目標 → `sub_E2AB60` |
| `CSpellRange` | `0xE26A30`／`0xA25E30` | `cccdhh`（目標 id、x、y） | 距離超過 → 訊息 4220 |
| `CSpellTargetCallback` | `0xE2B1F0`／`0xA2A5F0` | `cccd` | 游標選完目標後 |
| `CSpellOther`、`CSpellLocation`、`CSpellTeleport`、`CSpellPledge` | `0xE253C0`、`0xE216A0`、`0xE2B6C0`、`0xE26170` | `cccdhh`／`ccchh`／`ccchhh`／`cccd` | |
| 自動反擊（技能 186） | `0xE24FD0`／`0xA243D0` | `cccdhh` | 從 `S_ATTACK` 處理函式內呼叫 |

逐一看過反編譯：**沒有任何一個呼叫自身物件的 vtable+76（開始動作，`sub_A467A0`）**，也沒有改朝向。施法動作是收到伺服器的 `S_ATTACK`／`S_ATTACK_MANY`／`S_ACTION` 時才播（§2）。

### 1.2 已驗證：冷卻由自身外型的動作 18／19 長度算出

- `sub_E246E0`（FO `0xA23AE0`）：冷卻 = `sub_A3BC30(自身, 18 或 19, 0)` + 技能資料 `+56`。用 18 或 19 由技能資料 `+60`（`sub_E172D0`）決定。
- `sub_A3BC30`（FO `0x63B030`）＝某外型某動作的總毫秒：逐格加總 list.spr 的影格時間，再套用自身速度修正（`+547` 旗標或 `sub_A41C30` → ×29/32；`0x14EBF88` 1→×3/4、2→×2、3→×7/8；`0x14EC00C` 1／6→×3/4、3→×7/8 或 ×3/4、5→×3/8；`+544`→×2）。外型沒有該動作時固定 1234 ms。這組倍率與 AN§1.2 表情節流相同。
- `sub_E24870`（FO `0xA23C70`）：記下「現在＋冷卻」。`sub_E223F0`（FO `0xA217F0`）在「現在 < 冷卻結束」時直接拒絕，不出訊息。
- 技能資料 `+56`、`+60` 的來源檔（客戶端技能表）本輪沒有追，**待驗證**。

### 1.3 推測：沒有目標時進入選目標游標

`sub_E2AB60`（FO `0xA29F60`）：若上一個目標還在 15 格內就直接用它；否則呼叫 `sub_F691C0(…, 15, 179)` 進入選目標模式（範圍 15）。參數 179 推測是游標編號，未對資源。

## 2. 收包後的施法者動作與特效分派（T101）

### 2.1 已驗證：施法者

| 封包 | 施法者處理 | 朝向 |
|---|---|---|
| `S_ATTACK` | `sub_A3D050`（FO `0x63C450`）：把「目標＋傷害」掛在施法者 `+316`，特效物件掛在 `+428`，`+424`=1，再開始動作（vtable+76） | 目標物件存在 → **轉向目標目前位置**（`sub_A40EC0`）；否則用封包朝向 |
| `S_ATTACK_MANY` | `sub_A3DC10`（FO `0x63D010`）：有特效物件時目標清單**掛在特效上**，施法者只掛特效；沒有特效時清單掛在施法者 `+316` | 轉向**第一個目標**目前位置；否則用封包朝向 |
| `S_ATTACK_ALL` | `sub_A3D8F0`：清單掛在施法者，不轉向 | — |

施法者正在做動作（`sub_A3EBF0`）時，改用 `sub_A3C5A0`／`sub_A3C710`／`sub_A3C6C0` 把整包排進佇列（`sub_A40250`），等目前動作結束再播。施法者不在畫面上時，特效直接開始（`S_ATTACK` 尾段 `else if (v80) start`）。

**釋放時機：** `sub_A467A0`（開始動作，FO `0x645BA0`）在第 0 格就有 `!` 時立即釋放；否則由每格回呼 `sub_A4B060`（FO `0x64A460`）在**下一個 `!` 格**釋放：
- 有特效物件（`+428`）→ `sub_A46240`（FO `0x645640`）啟動特效（vtable+24）；
- 否則對 `+316` 清單每一筆傷害 ≠0 的目標呼叫 `sub_759B30` → `sub_758050`（受擊：目標播動作 2 或特殊受擊）。

### 2.3 已驗證：飛行的計算

`sub_7C3950`、`sub_8211E0`、`sub_83CD40`、`sub_81CF30`（各類別 vtable 第 6 格）在**啟動那一刻**把終點改成目標的目前位置（目標存在時），重算朝向（`sub_F1A340`），步數 = 起終點的切比雪夫距離（`+680`）。每步位移由 `sub_F1A190` 以 16.16 定點算出，長軸一步一格。到達（`sub_4F8D40`）或步數用完就結束。

### 2.4 已驗證：受擊判定的原版缺陷

預設特效 `sub_8ABC10` 的 `!` 受擊迴圈逐筆檢查「第 i 筆傷害 ≠0」，但呼叫受擊時**固定取第 0 筆的目標與傷害**：反組譯 `0x8AC26E`（FO `0x4AB66E`）`imul eax, 0`、`0x8AC28B` `imul eax, 4…0`。所以 **S42 用預設類別的特效時，只有第一個目標播受擊動作**（n 筆有傷害就對第一個目標觸發 n 次）。kind 5（`sub_83CE90`）與「沒有特效、清單掛在施法者」（`sub_A4B060`）的迴圈都正確使用第 i 筆。

### 2.5 已驗證：其他附帶規則

- `S_ATTACK_MANY` 的 `type` byte 存到特效 `+9`。`+9`≠0 時，特效第 1 格把全域明暗 `L`（`0x14EBFF4`，AM§1）暫時改成 `min(15, L+5)`，最後一個這種特效結束時還原（計數 `0x13CE258`）。3.81 的 type 8 會觸發這個提亮。`S_EFFECT_LOC` 的 gfx 2028–2056 也帶這個旗標。type→`+9` 的對應是依欄位順序判斷（推測，可信度高）。
- 每個目標在收包時立刻呼叫 `sub_A4DF10`（FO `0x64D310`）：與自己相關時觸發戰鬥音樂（SD 文件的戰鬥音樂）。
- `S_ATTACK` 尾端 byte＝2 時：尾端 word 是有效 gfx 就存成命中時的附加特效，否則在施法者位置放 3671；尾端 byte＝4 時在目標位置放 13417（`sub_A3D050`）。3.81 這兩欄送 0，不會觸發。
- `S_EFFECT`（S55）：收包立刻在物件位置以物件朝向播放，不等動作；6985、7179、8150、8152、8981、7834、7836 會跟著物件。`S_EFFECT_LOC`（S106）：立刻在座標播放。

## 3. S42 範圍法術的時序（T101）

依 §2，原版一個 S42 的順序是：

1. 收包：每個目標做戰鬥音樂判定；施法者轉向第一個目標，開始動作（忙碌時排隊）。
2. 施法者動作到第一個 `!` 格：啟動**一個**特效（預設類別在封包 x,y＝施法者位置；kind 5 從 x,y 飛向第一個目標）。
3. 受擊：
   - 預設類別：特效自己的每個 `!` 格，只對**第一個**目標（§2.4）。特效圖沒有 `!` 格時，沒有任何受擊動作。
   - kind 5：飛到時對每個傷害 >0 的目標受擊，並在每個目標位置放 param gfx。
   - 沒有特效（gfx<0 或施法者不在）：施法者 `!` 格對每個傷害 ≠0 的目標受擊。

## 4. 箭矢 gfx（T101）

伺服器（只讀原始碼）決定 gfx：弓有箭 → `resolveProjectileGfx(pc, weapon, arrow, 66)`；魔法弓無箭 → 預設 2349；鐵手甲飛刀 → 預設 2989。優先順序：變身的 `arrowSpr` → 彈藥模板 `arrowSpr` → 武器能力 `ARROW_SPR` → 預設（`L1PolyMorph.java:321`）。個別道具的 `arrowSpr` 在資料庫，本輪**不查 DB**，只列預設值。

| gfx | list.spr 名稱 | 109 kind／param | 原版表現 |
|---|---|---|---|
| 66 | arrow | 3／−1 | 30 ms／格飛行，到達時受擊，無落點圖 |
| 2349 | energy arrow | 3／**219** | 同上。kind 3 類別**不讀 param**，所以原版**不畫 219** |
| 2989 | sting knife | 3／−1 | 同 66 |

## 5. 七職業基本技能（T113–T119）

原版沒有逐技能的表現程式：施法動作（18／19）、特效 gfx、飛行與受擊全部來自回包＋§2 的 109 規則。所以 T113–T119 的一致性**等於 T100＋T101 的一致性**，差異見第 6 節；只要修好 SV#1–SV#8，各職業技能自動一致。各技能實際用哪個 gfx 在伺服器 DB 的技能表，本輪不查。
