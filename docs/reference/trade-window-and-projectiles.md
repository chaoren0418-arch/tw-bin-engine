- `sub_A59780` 的 switch 有 0／1／13／14（以及 15、16）。

### 1.4 列版面（已驗證，`sub_A27EF0`／FO `0x6272F0`、`sub_A29AA0`／FO `0x628EA0`）

座標相對視窗原點。列原點 `(19, 38 + 36k)`，k＝0…6。

### 1.5 數量輸入（已驗證，`sub_A2AD00`／FO `0x62A100`、`sub_A2C040`、`sub_A2BFA0`、`sub_A2AFA0`）

- 點「＋」／「－」：按下記錄方向、放開才加減 1。拖出熱區再拖回來，按下狀態會切換（`+152`）。按下時「＋」畫 surf 555、「－」畫 557。
- 鍵盤：數字鍵把數量 ×10 再加該數字；Backspace 除以 10。鍵碼 4203／4205 等同「＋」／「－」。
- 「＋」到上限後回到 0；「－」到 0 後跳到上限（`+296`）。
- **買（模式 0）的單筆上限依單價：**

  | 單價 | 上限 |
  |---|---|
  | <1000 | 9999 |
  | <1 萬 | 999 |
  | <300 萬 | 20 |
  | ≥300 萬 | 1 |

  另外，單價 ≥1000 萬時，「＋」「－」一律限 1。
- 其他模式的上限是物品數量（`+296`）。

### 1.8 3.81 是否支援

- **封包：** 修理（S83／C118／C20）、學魔法（S41／C39、S13／C191）、商店（S70／S65／C161）的欄位，都和 TW16 `TradeWindow` 的讀寫格式一致（1.1、1.6）。傭兵與弓兵（模式 15、16）伺服器不支援，**不建議做**。
- **視窗：** LiTo 快照找不到 `TRADE_WINDOW`、`uiextra86`、`TradeWindow` 等字串，也**找不到任何 `.xml` 字串**。它讀的是 `LiTo/LTsurf.pak` 等自己的資源包。所以 3.81 的交易窗很可能是寫死在程式裡，不是讀 `uiextra86.xml`（**推測**，可信度中：快照不一定完整；Themida 可能在使用前才解出字串）。
  - 這和 [`windows-2.md`](windows-2.md) 把本機 `uiextra86.xml` 稱為「3.81 世代設定」的說法有出入。本機 `Tile.pak` 的 XML 至少是 TW16 會讀的版本。
  - 引擎目前以 TW16 為準，所以 R2-E 照本節做沒有問題。3.81 真機畫面若不同，以真機截圖為準。
