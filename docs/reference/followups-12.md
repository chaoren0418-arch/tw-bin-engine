## 1. 1:127：3.81 倉庫的數量輸入（已驗證）

### 1.1 結論

**3.81 沒有數量提示框，也不會直接整疊存取。** 倉庫（存入與取出）用舊式**清單窗**，每一列右邊有「**▼ 數量 ▲**」，數量**從 0 開始**；只有數量大於 0 的列會送出。改數量有三種方式：

1. **點 ▲／▼**（每列兩顆 12×12 的小鈕）：▲＋1，超過持有量變回 0；▼－1，**在 0 按 ▼ 直接跳到持有量（＝全部）**。
2. **先點一下那一列（選取），再用鍵盤打數字**：0–9 逐位輸入（新值＝舊值×10＋數字），超過持有量就停在持有量；Backspace 刪最後一位；**點列會把輸入緩衝清成 0**。
3. **選取後按數字鍵盤的 ＋／－**（鍵碼 4203＝`0x1000|VK_ADD`、4205＝`0x1000|VK_SUBTRACT`），效果同 ▲／▼。

Enter 在清單裡只回「已處理」，不送出；送出是按確定鈕。非堆疊物品的持有量是 1，所以也要按一次 ▲ 或 ▼ 才會被選。

### 1.2 依據

**取出清單（S_RETRIEVE_LIST，客戶端編號 0x31）**：處理函式 `sub_4AC9B0`（VA `0x4AC9B0`／快照 FO `0xAC9B0`）。
- 先用格式 `"dhc"`（`0x6343AC`）讀 NPC 編號、筆數、類型；類型 11 走另一條路（不是倉庫）。
- 每筆用 `"dchcdcs"`（`0x6344DC`）讀：物件、使用類型、圖示、祝福、**數量**、鑑定、名稱，和 `S_RetrieveList.java` 的欄位一致。
- `0x4ACC57` 呼叫 `sub_4D8B30` 把每筆加進清單 `dword_834C1C`；列的建構子 `sub_4D8310`（`0x4D8343`）把**選取數量 `+0x88` 設成 0**，持有量放在共用基底（`sub_442860`）的 `+0x74`。
- 收尾 `0x4ACC6F`：**類型 12 才讀最後的 `D`**，其他類型用預設 **30**（`0x4AC9D2` `mov [ebp-0x20], 0x1E`），存到窗物件 `dword_834C18+0x24`；然後 `sub_4EBCB0(類型)` 開窗。

**存入清單**：NPC HTML 的動作 `deposit`／`deposit-pledge`／`deposit-elven`（字串 `0x502FE4`／`0x502FD4`／`0x502FC4`），在 `sub_407C70` 裡由**客戶端自己**用背包建清單，不送封包：
- `sub_4D9C70`（`0x4D9C70`）逐一檢查背包，名稱含 desc **9「揮舞」**或 desc **117「使用中」**的不列（用本機 `desc-c.tbl` 核對，兩筆都吻合）；其餘用 `sub_4D8AA0` → `sub_4D82C0` 加列（持有量取背包的 `+0x74`，選取數量 `0x4D82F8` 設 0）。
- 開窗類型：`deposit`＝2、`deposit-pledge`＝4、`deposit-elven`＝8（同一函式還有一條開 10 的分支，動作名稱未查）。

**列的畫法**：`sub_4D83B0`（`0x4D83B0`）。名稱畫在列左上（x＋38, y＋3）；第二行右邊用 `"%u"` 畫**選取數量 `+0x88`**，數字左邊畫圖表 556（▼，按下 557）、右邊 x＋180 畫圖表 554（▲，按下 555）。兩顆鈕的位置存回列的 `+0x8C`／`+0x90`／`+0x94` 給滑鼠判斷。（圖編號是 `dword_834BD4` 圖表的索引，對到哪個 surf 檔本輪沒查。）

**滑鼠**：清單的 `sub_4D8C40`（`0x4D8C40`），列高 34。
- 513／515（左鍵按下／雙擊）：選取那一列（`sub_450940`，單選），判斷是否按在 ▼（`+0x70`＝−1）或 ▲（＝1）上；**同時把輸入緩衝 `+0x90` 清 0**（`this+144`）。
- 514（放開）且還在鈕上：▼ → `sub_4D8830`、▲ → `sub_4D8870`。
- `sub_4D8830`（▼）：數量 > 0 就 −1；**等於 0 就設成持有量**；再夾到清單上限（見 1.3）。
- `sub_4D8870`（▲）：+1；超過持有量（且持有量 ≠ 0）就歸 0；再夾到清單上限。
- 雙擊和單擊走同一條，沒有「雙擊＝全部」。

**鍵盤**：清單 vtable `0x4FA894` 第 7 格（`0x4FA8B0`）＝`sub_4D9770`（`0x4D9770`），作用在第一個被選取的列（`sub_4D96E0`）：
- 48–57（'0'–'9'）：`緩衝 = 緩衝×10 + 數字`；上限＝持有量 `+0x74`（若清單上限不為 0 且 ≤ 持有量，改用清單上限）；超過就設成上限；再 `sub_4D88D0` 寫回列的 `+0x88`。
- 8（Backspace）：`緩衝 /= 10`。
- 4203／4205：同 ▲／▼。
- 13（Enter）：回傳 true，不做別的。

**送出**：確定鈕 `sub_4DAB80`（`0x4DAB80`）。倉庫類型（2、3、4、5、8、9…）進 `sub_4D9A20(清單, 類型)`：
- `sub_4D9930` 只收**選取數量 ≠ 0** 的列，每列寫 `D 物件, D 數量`，後面接 5 byte 檢查碼（類型 14 除外）。
- 連線狀態（`dword_64AF98 == 4`）用 `"hcdch"`：長度、219、NPC 物件（清單 `+0x6C`）、類型、筆數，對到 `C_Result.java` 的 `D npc, C type, C size, C …` 後接 `(D, D)×n`。
- 沒按確定就關窗時（窗 `+0x10` 旗標仍是 0；確定鈕會設成 1），同一個窗的另一個 vtable 函式 `sub_4DA270`（vtable 格 `0x4FA914`）對類型 3／5／9 送 `"cdch"` 0x28（筆數 0），推測是「關窗不取」。

**取出手續費顯示**：`sub_4DA9D0`（`0x4DA9D0`）對類型 3、5、12 畫「**已選列數 × 30**」和身上的金幣；存入類型只畫金幣。也就是**每取一種物品收 30 金幣**，與數量無關。

## 2. FU9§17 的其他 3.81 問題

### 2.1 `ADENA_EXCHANGE_WINDOW` 誰開（已驗證：3.81 沒人開）

- 快照全部非殼區段用 ASCII 與 UTF-16LE 搜尋：`ADENA_EXCHANGE`、`TRANSACTION_WINDOW`、`WAREHOUSE_WINDOW`、`uiextra`、`uimagicitem`、`uistatus`、`ReWareHouse`、`CHEST`、`.xml` **都是 0 筆**；`xml` 只出現在 `.rsrc` 的 manifest（`0x83966A` 等）與殼區段。packed 的 `LiTo.bin` 也搜過，一樣 0 筆。

### 2.3 個人商店兩行訊息的 0xFF（已驗證）

收到動作 70（`S_ACTION` 0x20 → `sub_4A5A90`，動作值 70 時）把動作後面的位元組交給 `sub_4E9140`（`0x4E9140`）：

- 先複製到 80 byte 的暫存（遇 0 停）。
- 逐字放進角色物件 `+0xC6` 開始、每行 41 byte 的緩衝：**遇到 0xFF 就結束這一行、換下一行**；第一行**到第 40 byte 還沒遇到 0xFF 就強制換行**（第 41 個字元當第二行開頭）。
- 顯示：`sub_414320`（`0x414320`）每次把 `+0x118` 反轉，第二行（`+0xEF`）不空且輪到時顯示第二行，否則第一行；文字交給 `sub_4143D0` 畫在頭上（`byte_62C9C9` 為真才畫，推測是「顯示對話」類選項），然後 `sub_4D65F0` 排 **5000 ms**（`0x4143BE` `mov ecx, 0x1388`）後再呼叫自己。
- 結論：**兩行訊息在頭上輪流顯示，每 5 秒換一行**；只有一行時就一直顯示那一行。第三行以後（多個 0xFF）存了但不會顯示。
