## 1. 表情動作（C120 → 動作 66–69）

### 1.1 已驗證：入口與項目

3.81 伺服器的 C120 是 `C_ExtraCommand`：讀 `C(actionId)`，只接受 `ACTION_Think`=66、`ACTION_Aggress`=67、`ACTION_Salute`=68、`ACTION_Cheer`=69，以 `S_DoActionGFX(objId, actionId)` 廣播。TW16 送的是自己的編號 **opcode 50、格式 `cc`**（`C(50) C(action)`）。動作值 66–69 與伺服器相同，**直接當 sprite 動作編號**（每個 gfx 有 121 個動作槽，表在 `0x153CE78`，bss）。

TW16 有兩個入口，項目都是四個：

| 入口 | VA／FO | 說明 |
|---|---|---|
| 動作槽註冊 | `sub_AD8EF0`／`0x6D82F0` | 以字串 `Action_SocialAction1`～`4`（`.rdata` `0x119F93C`／FO `0xD9E53C` 起）註冊四個回呼：`sub_ADACB0`、`sub_ADADE0`、`sub_ADAED0`、`sub_ADAFC0`（FO `0x6DA0B0`、`0x6DA1E0`、`0x6DA2D0`、`0x6DA3C0`） |
| 選單／快捷命令 | `sub_8C14F0`／`0x4C08F0` 的命令 32817～32820；`sub_8C2290`、`sub_8C5380` 是另外兩個 UI 情境的同型處理 | 與動作槽同一組邏輯，但重映射略有不同（下表） |

**預設對應（未變身的職業外型）：**

| 項目 | 動作 | 伺服器常數 |
|---|---|---|
| SocialAction1／命令 32817 | **68** | Salute（敬禮） |
| SocialAction2／命令 32818 | **69** | Cheer（歡呼） |
| SocialAction3／命令 32819 | **67** | Aggress（挑釁） |
| SocialAction4／命令 32820 | **66** | Think（思考） |

顯示文字在 `Text.pak`，本輪沒解，中文名稱沿用伺服器常數的意思（**待驗證**）。

- **立即型** `sub_4FBA70(action, hold)`（FO `0xFAE70`）：送 `cc 50 action`，**同時呼叫自身 vtable+76 立即在本地播放**，沒有冷卻。`hold=1` 時另外排 1234 ms 的計時器 `sub_4F94F0`（FO `0xF88F0`）。

- 兩者都要求自身不在忙碌動作中（`sub_A3EBF0`）且 `0x153CE5F`＝0。

**動作槽路徑（`sub_ADACB0`…）：**

| 外型 | 槽 1 | 槽 2 | 槽 3 | 槽 4 |
|---|---|---|---|---|
| G1、G1'（槽 1 另含 gfx 3750、3775、3858、10413） | 立即 68 | 立即 69 | 立即 67 | 立即 66（**只有 G1**，G1' 走其他） |
| G2、G3 | 立即 67 | 立即 68 | 立即 69 | 節流 66 |
| G4 | 立即 66 | 立即 67 | 立即 68 | 立即 69 |
| gfx 10413 | 立即 68 | 不送 | 不送 | 節流 66 |
| 其他（一般變身） | 節流 68 | 節流 69 | 節流 67 | 節流 66 |

**選單路徑（`sub_8C14F0`，命令 32817～32820）與上表的差別：**

- G2 前三項送 68／69／67，G3 前三項送 67／68／69，都帶 `hold=1`；第 4 項兩者都走節流 66。
- G4 保留原動作（68／69／67／66）並帶 `hold=1`。
- gfx 10413 第 1 項改為立即 68 帶 `hold=1`。gfx 11635、11650 只有前兩項以 `hold=1` 送 68／69，其餘走節流。
- G1' 在第 4 項也走立即型。

**推測：** `hold=1` 的 1234 ms 計時器是讓坐騎類外型播完後回到原姿勢；未追 `sub_4F94F0` 內容。

### 1.3 已驗證：播放

`S_ACTION`（`sub_92CB70`）讀 `D(objId) C(action)`，把 action 設成物件目前動作；66–69 沒有特別分支。動作缺圖時的退回規則見 3.4（同一套）。

### 2.4 已驗證：顏色與字型

**文字函式** `sub_841770(surface, str, len, x, y, 字色, 外框色, flag)`（FO `0x440B70`）：

- 支援 `\f<c>`（換色）與 `\a<c>`（palette `0x1369D58`）跳脫。
- 字碼頁 950 時用 GDI 字型 **MingLiU 12 px**、粗細 400、字集 0x88（`sub_8444A0`／`0x4438A0` 建立）。先在上下左右 ±1 px 畫外框色，再畫字色（`sub_83E490`／`0x43D890`）。
- 其他字碼頁用點陣字 `font\eng.fnt`（6×12）／`font\kor.fnt`（12×12），外框字形 8×14／14×14 畫在 (−1, −1)。
- **推測：** TW 版的字碼頁 `0x13CE508` 是 950。

**名稱與稱號都用物件 +204 當字色、palette[0]（黑）當外框。** 稱號沒有獨立顏色。

palette 在 `0x1369D70`（`.data`，FO `0xF68570`），RGB555；`0x13CC950` 旗標成立時由 `sub_7F6720` 轉成 565：

| 索引 | 值 | 用途 |
|---|---|---|
| 0 | `0x0000` | 外框（黑） |
| 1 | `0x001F` | 怪物等級差外框（藍） |
| 3 | `0x7C00` | gfx 2715 的名稱（紅）；等級差 ≥10 |
| 14 | `0x7FFF` | 預設名稱色（白） |
| 16 | `0x4200` | 等級差 3–9 |
| 22 | `0x02E0` | 等級差 ≤ −2 |
| **42** | **`0x767D`** | **粉紅名**（約 RGB 232,152,232） |
| 54 | `0x4B7F` | +252 行（淺藍） |

**+204 只有 4 個寫入者**（`fieldw.py` 全庫掃描）：

1. **正義值色** `sub_A406C0`（FO `0x63FAC0`），L＝+192：
   - L ≥ 500：v = min(31, ((L − 500) >> 8) + 1)，色＝(R=31−v, G=31−v, B=31)，越正義越藍。
   - 0 ≤ L < 500：白 `0x7FFF`。
   - L < 0：v = min(31, ((−L) >> 6) + 1)，色＝(R=31, G=31−v, B=31−v)，越邪惡越紅。
2. **更新正義值** `sub_A450C0`（FO `0x6444C0`）：寫 +192 後，若仍是粉紅名（vtable+124 > 0）就保持 palette[42]，否則重算正義值色。
3. **粉紅名** `sub_A452C0`（FO `0x6446C0`），見 2.5。
4. **複製物件建構子** `sub_5FC230`（FO `0x1FB630`）：預設 palette[14]，有來源物件就複製其 +204。

**特例：**

- gfx 2715 在非戰爭時名稱固定用 palette[3]。
- 「怪物等級差」選項（`0x13CE3FE` ∈ {1,5}，物件種類 10）把外框改成等級差色，見上表。**推測**種類 10 是怪物。

### 2.5 已驗證：粉紅名

`S_CRIMINAL`（`D objId, C 秒數`）→ vtable+128 → `sub_A452C0`：

- 物件種類 8 不處理。

### 2.6 已驗證：決鬥對手

### 2.7 已驗證：敵對血盟

`sub_A45920`（設血盟名）只在戰爭模式 `0x153CE76` 成立時判斷：

- 血盟名在戰爭名單中（`sub_874FD0` 迭代）→ +197＝2、+196＝1。

### 2.8 已驗證：盟徽取得與快取

## 3. 變身（S76）時的武器姿勢與動作

### 3.1 已驗證：動作編號＝姿勢＋偏移

- 物件 +194 是**武器姿勢**（走路動作的基底）。
- 合法值是 `sub_A4ADD0`（FO `0x64A1D0`）列的 {0, 4, 11, 20, 24, 40, 46, 50, 54, 58, 62, 83}。
- 攻擊＝姿勢＋1、受擊＝姿勢＋2、待機＝姿勢＋3：`sub_A3EBF0` 用 +3，`sub_A407D0` 用 +2。

### 3.2 已驗證：TW16 `S_POLYMORPH`

格式 `D objId, H gfx, C 姿勢, H (未用), C 有名稱 [, S 名稱]`。欄位順序由反組譯的推入順序確認（`[ebp-14h]`＝gfx、`[ebp-0Dh]`＝姿勢、`[ebp-0Eh]`＝名稱旗標）。

處理順序：

1. 有名稱旗標就換名稱（+232）。
2. gfx 為 6080／6094 時附加特效 gfx 6099。
3. 自己且姿勢從 >0 變成 0 時，顯示系統訊息 #1027（文字待驗證）。
4. list.spr 欄位 113（`0x13CD870`）非 0 時附加該 gfx 的特效。
5. 物件忙碌時延後（`sub_A3C930`），否則 **`sub_A43B50(gfx, 姿勢)`**（FO `0x642F50`）：寫 +10＝gfx、+194＝姿勢、目前動作＝姿勢、影格歸 0；+40 旗標取 list.spr 欄位 104（`0x13CD84C[gfx]`）。

**伺服器（3.81）差異：** `S_ChangeShape` 只送 `H(polyId), H(weaponTakeoff ? 0 : 29)`，**不帶姿勢**。TW16 由伺服器明確給姿勢。3.81 客戶端怎麼由 29／0 推姿勢，本輪無從得知（**推測**：0＝卸下武器、姿勢歸 0）。

### 3.3 已驗證：`S_WIELD`

格式 `D objId, C 姿勢, C (未用)`。姿勢不是 70（個人商店）時清除商店相關狀態；接著呼叫 `sub_A48A70(姿勢)`（FO `0x647E70`）：姿勢有變才寫 +194、把動作設成姿勢、影格歸 0。

### 3.4 已驗證：缺圖退回

`sub_A3EF40`（FO `0x63E340`）在每幀取圖時（表查詢 `sub_506210`／`0x105610`）處理缺圖：

1. 目前動作在 (gfx, 動作, 方向) 沒有影格，且動作不是 119／120 時：
   - 動作 >0 → 若 (gfx, 姿勢) 有圖就**改播姿勢動作**；否則**把 +194 改成 0、播動作 0**（自己會通知 UI）。
2. 影格鍵為 −1 時改用姿勢動作那一格的鍵。
3. sprite 檔不存在（非自己）→ gfx 改成 **1120**、動作 0，並記錄 `Sprite file %d-%d.spr doesn't exist`。

所以**變身成沒有該武器動作的外型時不會擋操作**：表情、攻擊等動作缺圖時會逐級退回。

### 3.5 已驗證：特殊外型

- **騎馬頭盔 6080／6094：** 每次動作循環結束時（`sub_A43560`／`0x642960`）切換 +548，姿勢在 0↔20、24↔62 之間互換。表情另有重映射（1.2）。
- **list.spr 欄位 108**（`0x13CD850[gfx]`）＝2 的外型：
  - 動作 44 播完 → 姿勢改為 4，或在欄位 111（`0x13CD858`）非 0 時改為 11；+199＝2。
  - 動作 45 播完 → 姿勢 0；+199＝1。
  - 推測是收刀／拔刀動畫。
- **伺服器（3.81）** 變身中只接受 gfx 6080／6094 的表情（`C_ExtraCommand`）；TW16 客戶端則對一般變身仍以節流型送出。

## 7. 重跑方式

1. 準備：把 P01 IDB 複製到 `scratch/rea/ida/tw16.idb`，核對 SHA `3a0bf206…7e82f`。
2. IDA 查詢：依 `docs/reference/rea-scripts/t160/queries.txt` 執行：
   ```
   powershell -NoProfile -File docs\reference\rea-scripts\t160\run.ps1 -Script decomp.py -Out emote -Arg "<VA,...>"
   ```
   - 輸出在 `scratch/rea/out/<Out>/`。
   - `run.ps1` 用 `J:` subst；被占用時直接退出，不會卸除別人的對應。
   - `mkfunc.py`／`disasm.py`／`decomp.py` 可能在**副本**上補建函式；原 IDB 不動。
3. 不需 IDA：
   ```
   py -3 -I docs\reference\rea-scripts\t160_opmap.py
   py -3 -I docs\reference\rea-scripts\t160_xcheck.py scratch\rea\out\xcheck.json
   ```
   前者印出處理函式的 TW16 封包名稱；後者印出 TW13 指紋。
