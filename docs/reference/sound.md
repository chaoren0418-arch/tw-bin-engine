# 原版音效播放策略（T163／#431）

**範圍：** 補完 #417 的音效結論，涵蓋 T105（S22 音效）、T047 系列（戰鬥音效）、T165（`<` 模式）、T166（`^` 環境音）。

**方法：** 照 #417，全程唯讀靜態分析。

- 主樣本：未加殼的 `TW1608262200.bin`（SHA-256 `e12949cf…641a2`）。
- 工具：IDA 7.7＋Hex-Rays，用 P01 IDB（SHA `3a0bf206…7e82f`）在 `scratch/` 的副本。複製後重算 SHA，與原檔相同。
- 地址寫法：VA（ImageBase `0x400000`），括號內是 File Offset。`.text` 的 File Offset = VA − `0x400C00`。
- 交叉驗證：`TW13081901.unpacked.exe`（SHA `653da514…5c62a4`）。
- 函式名是 IDA 自動命名。偽碼型別是推導結果，不等於原始碼。

**重跑方式：** 腳本在 `docs/reference/rea-scripts/`。

- `ida_snd.py`：列出 Miles 匯入與音效字串的使用者。
- `ida_dis.py`：依清單反編譯（`dec`）、反組譯（`dis`）、列引用並反編譯（`xdec`）。
- `xver_snd.py`：TW13 交叉比對，路徑由參數傳入。
- `run_ida.ps1`：新增 `-Script`、`-Drive` 參數，可以避開其他任務占用的 subst 磁碟代號。

**標記：** 「已驗證」表示機器碼或偽碼直接可見；「推測」表示依名稱、慣例或間接證據；「待驗證」表示本輪沒查到。

## 1. 總覽：三條音效管線

原版有三條互相獨立的管線，都用 Miles Sound System：

| 管線 | API | 用途 | 入口 |
|---|---|---|---|
| **A. 取樣（sample）** | `mss32midi!_AIL_quick_*`（`quick_load`／`copy`／`play`／`set_volume`／`halt`） | 影格音效（`<`、`[`、`^`）、伺服器音效封包、UI 音效、`envsound.def` 環境音 | `A06020`（`0x605420`）是唯一呼叫 `AIL_quick_play` 的函式 |
| **B. 音樂串流** | `mss32!_AIL_open_stream`／`start_stream`／`set_stream_loop_count`／`set_sample_volume_pan` | 背景音樂 `sound\music%d.mp3`、場景音 `scene%d.mp3`、語音 `voice\%s-%c.mp3` | `8F2D10`（`0x4F2110`）、`8F30E0`（`0x4F24E0`） |
| **C. MIDI 後備** | `WINMM!mciSendCommandA` | 找不到 `sound\music*.mp3` 時改播 `sound\%d.mid` | `8F63D0`、`8F5510` |

**已驗證：** 匯入表與使用者如上。初始化在 `8F1FA0`（`0x4F13A0`），參數如下：

- `AIL_quick_startup(1, 0, 22050, 16, 2)`
- `AIL_open_digital_driver(22050, 16, 2, 1)`

另外兩條規則：

- `music.cfg` 第一個字元是 `'1'` 時，整個音效系統都不啟動。
- `sound\music*.mp3` 一個都找不到時，設 `byte_13D3F88=1`，改走 MIDI。

## 2. 影格音效：`<`、`[`、`^` 的完整路徑

### 2.1 選擇（`sub_A3EF40`，`0x63E340`）

**已驗證，與 #417 相同，本輪補上精確分支：**

| 步驟 | VA（File Offset） | 內容 |
|---|---|---|
| 條件 | — | `a2 ≠ 0`，且自身角色 `dword_153CE60` 存在 |
| 抽候選 | — | 候選數 `+12` 為 0 或大於 5 時略過；為 1 時取第 0 個；其餘用 `rand() % n`。抽到 0 就略過，不重抽 |
| 通知 | `A3FB85`→`F804B0` | 先把 id 交給 `SoundHighlight` 系統（`F80130`／`F804B0`，字串 `SoundHighlight.xml`），用來決定是否壓低其他音量 |
| 分派 | `A3FBB8`（`0x63EFB8`）、`A3FC2E`（`0x63F02E`） | `+20 == 1`（`[`）呼叫 `A060F0`；`+20 == 2`（`^`）呼叫 `A06210(id, d²)`；其餘（`<`＝0）呼叫 `A060F0` |
| 呼叫點 | `A3FBFD`、`A3FCB9` → `A060F0`；`A3FC77` → `A06210` | `this` 是角色的**發聲體物件** `actor+0x278` |

結論：`<` 與 `[` 在原版的播放行為**完全相同**。`^` 是唯一走不同路徑的符號。

### 2.2 距離公式：`127 - 7*round(sqrt(d²))` **不是音量**

**已驗證：**

- `A3FB3B` 呼叫 `A43380`（`0x642780`），算出 `(int)(sqrt(d²)+0.5)`。
- `A3FB43..A3FB4D`（`0x63EF43`）算 `127 − 7*r`，結果存入 `[ebp+var_DC]`。
- `A3EF40` 全函式反組譯（`A3EF40..A400D0`）中，`var_DC` **只寫入這一次，從未讀取**，是死碼。
- TW13 的 File Offset `0x1AA89F` 有同樣的位元組（`6B C0 07 BA 7F 00 00 00 2B D0`），而且只出現一次。

d² 的算法：`d² = (x'自 − x'它)² + (y自 − y它)²`。其中 `x' = ((actor+0x10 − 0x8000) >> 1) + 0x8000`，`y = actor+0x14`。這個 d² **只用來排序 `^` 的音源槽**（見 2.5）。

**推測：** `+0x10` 的單位是 `+0x14` 的兩倍，原版先除以 2 才和 y 同尺度。

### 2.3 真正的距離衰減（`A3FCBE..A3FD7B` → `A091C0`）

**已驗證：** 每次 `A3EF40` 跑完音效分支後，只要自身角色與發聲體都存在，就執行下列計算：

```
nx = |(自.x − 它.x) >> 1|,  ny = |自.y − 它.y|
若 nx + ny > 14：nx = 14, ny = 0
音量 vol = 100 − 14·(nx² + ny²) / 20     （整數除法；A091C0 會把負值夾為 0）
第二值 ext = 64 − 63·(nx + ny) / 14      （夾為 ≥ 0）
A091C0(發聲體, vol, ext)
```

| 常數窗 | TW16 VA（File Offset） | TW13 File Offset |
|---|---|---|
| 曼哈頓距離上限 14 | `A3FD20`（`0x63F120`） | `0x1AAA0E` |
| `ext` 的 64、63、14 | `A3FD3C`（`0x63F13C`） | `0x1AAA2A` |
| `vol` 的 100、14、20 | `A3FD5F`（`0x63F15F`） | `0x1AAA4D` |

`A091C0`（`0x6085C0`）的動作：

1. 把 `vol` 寫入發聲體 `+12`，`ext` 寫入 `+16`。
2. 對發聲體名下每個 sample 呼叫 `A06D60`。
3. `A06D60` 執行 `AIL_quick_set_volume(h, 類別音量·vol/100/128, ext/128)`。

換算成距離（`nx`、`ny` 以格計）：

| 距離 | 音量 |
|---|---|
| 0～1 格 | 100% |
| 5 格（直線） | 83% |
| 8 格（直線） | 56% |
| 斜向 7＋7 | 32% |
| 11 格（直線） | 16% |
| 12 格以上（直線） | 0% |
| 曼哈頓距離 > 14 | 0%（夾成 14,0 後為負，再夾為 0） |

算式等於 `vol = 100 − 0.7·d²` 取整，`d² ≥ 143` 時為 0。

**推測：** `ext` 是 Miles 的第三參數 `extra_volume`。`A06C30` 的預設值是 `0.5f`（`0x3F000000`），數值落在 0～0.5，距離愈遠愈小。它不是左右 pan，因為取了絕對值，不分左右。實際聲學意義待驗證。

**時序（已驗證）：** 播放（`A060F0`／`A06210`）在 `A091C0` 之前執行。所以新音效第一次 `set_volume` 用的是發聲體**上一輪的** `vol`／`ext`，同一次更新稍後才被 `A091C0` 改成這一輪的值。

### 2.4 `<`／`[`：`A060F0`（`0x6054F0`）

**已驗證：**

1. 在發聲體的 sample 清單（`this+4`）裡，找同 id 而且**沒在播放**的 sample 重用。「播放中」由 `A05E70` 判斷：`AIL_quick_status == 3`。
2. 找不到就用 `A05410(id)` 新建一份 sample。新 sample 用 `AIL_quick_copy` 複製自全域的 id 快取；全域快取在 `A05560`，大小 `0x218`。
3. 依序呼叫 `A06C30`（設音量）、`A06AE0`（設 `ext`），最後 `A06020(sample, 1, 0, 1)`。

所以同一發聲體的同一 id **可以重疊播放**：前一個還在播時，會另開一份。

### 2.5 `^`：`A06210`（`0x605610`）

**已驗證：**

| 規則 | 內容 |
|---|---|
| 前提 | `id ≤ dword_153C78C`，而且發聲體目前 `vol`（`+12`）不為 0。太遠的音源不會啟動 |
| 槽表 | `dword_153C788 + 52*id`。**以音效 id 為索引，全世界共用**，不是每個角色一份。表由 list.spr 載入器 `87C890` 配置 |
| 槽格式 | `+0..+16`：5 個 sample 指標；`+20..+36`：5 個發聲體指標；`+40..+48`：5 個 `int16` 距離（d²）；`+50`：目前數量 |
| 已滿時 | 已有 5 個，而且新音源 d² 不小於第 5 個（最遠）時略過 |
| 不重複啟動 | 這個發聲體已有同 id 的 sample 正在播放時，直接返回 |
| 啟動 | 新建 sample，`A069F0(1)` 標記為「在槽表中」（`+4`），再呼叫 `A06020(sample, 0, 0, 1)` |
| 換入 | 啟動成功時：未滿就附加，數量加 1；已滿就 `A06E10` 停掉第 5 個（最遠），由新音源取代 |
| 排序 | 換入後按距離由近到遠泡泡排序 |
| 離開 | sample 解構（`A04A20`，`0x603E20`）時，從槽表移除並把後面的往前補 |

**`^` 是否循環：已驗證。** `A06210` 傳給 `A06020` 的次數是 0，`A06020` 在 `A060DD` 直接執行 `AIL_quick_play(handle, 0)`，同時把 sample `+4` 設成 1（循環旗標）。`A060F0` 傳 1。

**推測：** Miles 的 `loop_count = 0` 依 API 慣例是無限循環。這一點與 `A058E0` 的寫法一致：`envsound.def` 主環境音要循環時傳 1000。

**推測：**

- `int16` 存 d² 會在距離約 181 格以上溢位，但 `vol=0` 早已阻止啟動，實務上不會發生。
- `^` 的停止時機是發聲體被銷毀（`A04DF0` 停掉 `this[1]`）或 sample 被釋放；呼叫端沒有逐一追。播放期間的音量由 `A091C0` 每次更新時跟著距離變化。

**對照：** T162（#430）另外獨立查到同樣的槽表、公式與死碼結論，見 [`ambience-and-map-events.md`](ambience-and-map-events.md) 第 5 節。該節還補上 group 解構 `A04BF0` 會移除所有槽項，並確認**沒有「離開距離就停止」的分支**，遠了只是音量變 0。兩份文件的結論一致。

### 2.6 共用出口 `A06020`（`0x605420`）

`A06020(sample, 次數, 略過類別檢查, 套用冷卻)`，**已驗證：**

- 「略過類別檢查」為 0 時，`SoundVolume`、`EnvSoundVolume`、`VoiceVolume` 三個類別音量（`F7D5C0(0..2, 0)`）都是 0 就不播。
- 「套用冷卻」為 1 時，用 `A228B0` 取現在時間（QPC 或 `GetTickCount`）。如果比 `sample+8` 物件的 `+12` 早，就不播；否則把 `+12` 設成「現在 + 200」（`A060AE`：`add edx, 0C8h`）。
- 最後執行 `AIL_quick_play(h, 次數)`。

### 2.7 200ms 冷卻的範圍

**已驗證：**

- `sample+8` 是 `A05560` 建立、以 id 為鍵的**全域 sample 快取物件**，每個 id 一份，被所有 `AIL_quick_copy` 出來的實例共用。所以冷卻是**每個音效 id 一份、全域共用**，跨角色、跨管線都算。
- 會套用冷卻的路徑：
  - `A060F0`（`<`、`[`）與 `A06210`（`^`）：固定套用。
  - `A05980`、`A058E0`、`A06820`、`A08020`：固定套用。
  - `A05A40`：由呼叫端決定。
- `A06020` 本身也接受「不套用」。

**待驗證：** TW13 用同樣的位元組形狀找不到 `+200` 那一段（`xver_snd.py` 回 0 筆），可能是暫存器或堆疊配置不同。TW13 的冷卻本輪未交叉證實。

## 3. 伺服器音效封包（T105 的 S22）

**已驗證：**

- TW16 接收 dispatch `0x94761D` 的 **case 91** 呼叫 `94C4C0`（`0x54B8C0`）。
- `94C4C0` 以格式 `"ch"` 讀出 1 byte 模式與 1 個 `int16` id，依模式分派：

| 模式 | 呼叫 | 行為 |
|---|---|---|
| 0 | `A09310` → `A05980(id, 0)`（`0x604D80`） | 單次播放。類別是 `SoundVolume`，套用 200ms 冷卻。**這個 id 的全域實例還在播時就不播**（`A05EA0`） |
| 1 | `A08020(id)`（`0x607420`） | 類別是 `EnvSoundVolume`，`AIL_quick_play(h, 0)` 循環 |
| 2 | `A09110` → `A05A00(id)` | 停止這個 id |

- 檔案查找（`A05F00`／`A05F70`）：先 `sound\%d.mp3`，失敗才 `sound\%d.wav`。

**推測：**

- case 91 就是伺服器的 S22（`C(repeat) H(sound)`），依據是欄位形狀相同；TW16 與 3.81 伺服器的編號不同（#417）。
- 伺服器 `S_Sound` 的 `repeat` 在原版客戶端其實是**模式**，不是重複次數。`1-伺服器/src` 裡找不到帶第二參數的 `new S_Sound(...)`，所以實務上永遠送 0。

**另外一條：** 封包 108（`9357E0`，`0x534BE0`）的子類 `0x49` 用 `"d"` 讀一個 dword id，同樣走 `A09310`（單次）。

## 4. 背景音樂與場景音

### 4.1 音量類別（已驗證）

`lineage.cfg` 的讀取在 `814800`（`0x413C00`），寫回在 `814020`。`F7D5C0(類別, 套用修飾)` 回傳該類音量，修飾包含 `SoundHighlight` 壓低與靜音旗標 `+821`。

| 類別 | 設定鍵 | 用途 |
|---|---|---|
| 0 | `SoundVolume=` | 影格音效、單次音效封包、UI |
| 1 | `EnvSoundVolume=` | 環境音（`envsound.def`、模式 1 的封包）；`A06C30` 對有 `+5` 旗標的 sample 用這一類 |
| 2 | `VoiceVolume=` | 語音（sample `+6`） |
| 3 | `MusicVolume=` | 音樂串流 |

### 4.2 `music.def`（`8F21A0`，`0x4F15A0`；從資源包讀，不是散檔）

**已驗證：** 解析的格式如下：

- 第一段：`=N` 序列，填入索引表 `dword_13D3F90[202]`（預設 `i → i`），把固定用途的索引對到實際的 music 編號。
- `Planarization` 段：`<vol> id 百分比`，個別曲目的音量（上限 100）。
- `LoginMusic` 段：登入畫面曲目清單。
- 區域記錄：`地圖 x1 y1 x2 y2` 後接 `MUSIC 曲目…`、`INTERVAL 秒`、`SPRITE`、`SPAWN`、`BATTLE`、`DEATH`、`TWIN_SPRITE1`、`TWIN_SPRITE2`。

**待驗證：** 本機資源包內 `music.def` 的實際內容本輪沒有解出。

### 4.3 區域音樂選擇（`8F31F0`，`0x4F25F0`）

**已驗證：**

| 規則 | 內容 |
|---|---|
| 大編號地圖 | 地圖編號 `dword_138BE64 > 15000` 時固定回 **23** |
| 區域比對 | 找第一筆地圖相符，而且矩形為 0 或玩家在矩形內的記錄 |
| 頭目音樂 | `SPRITE`、`TWIN_SPRITE` 與目前登記的 sprite 相符時，改回該區的 `BATTLE` 曲。sprite 由 `8F3990` 登記，`8F3990` 的呼叫端是封包 226 的 `92CB70` |
| 一般曲目 | 從 `MUSIC` 清單隨機挑；清單多於 1 首時**不連續重複**同一首 |
| 曲間間隔 | 一首播完後，靜音 `INTERVAL` 秒再換下一首 |
| 找不到記錄 | 回 -1，不播 |

### 4.4 播放與切換（已驗證）

**單次播放，不循環：** 一般地圖音樂用 `8F3A40` 執行 `AIL_set_stream_loop_count(s, 1)` 後 `AIL_start_stream`。換曲由上面的區域規則負責。

**例外：** 以 `8F3AA0(1)`（loop 0）循環播放的只有兩處：

- 角色選擇（`EC4FE0`，狀態 20，索引 8）
- `EE5F50` 的介面

`8F3D70` 也會呼叫 `8F3AA0`，但循環與否由呼叫端參數決定；封包 108 子類 0x30 傳 0，所以是單次。

**兩種切換方式：**

| 函式 | 方式 | 細節 |
|---|---|---|
| `8F3B90`（`0x4F2F90`） | 立即切換 | 先 pause 再 close，然後開新串流 |
| `8F1C30`（`0x4F1030`） | 淡出後切換 | 每 50ms 執行一次 `8F1B60`，音量從 127 每次減 8，約 16 步、0.8 秒；到 0 後以全音量開新曲，**沒有淡入** |

**曲目音量（`8F1E50`）：** 淡出係數(0..127) × `MusicVolume` / 100 / 127 × 該曲 `<vol>`。`8F2D10` 帶旗標開串流時改用固定值 `0x3F4CCCCD`（0.8）。

**正在播的曲目不重開：** `8F6160(id)` 判斷「目前曲目＝id 而且串流狀態 4」。以下 5 首正在播時，`8F1C30`／`8F3B90` 不會打斷：`dword_13D3F90[12]`、`[13]`、`[15]`、`[16]`、`[17]`。

### 4.5 戰鬥音樂與其他情境（已驗證，索引意義屬推測）

| 觸發 | 位置 | 行為 |
|---|---|---|
| 自己參與攻擊 | `A4DF10`（`0x64D310`） | 記錄戰鬥時間 `dword_153CE70`，立即切到索引 **10**（對象類別 5）或 **9**（其他）。條件是戰鬥音樂選項開（`A4AD00(8)`）而且不在其他特殊狀態；`byte_13D42BC` 時改走區域淡出 |
| 離開戰鬥 | `F0F0C0` 主迴圈（`F10A37`） | 每秒檢查一次；上次戰鬥（`dword_153CE70`）與另一時間戳 `dword_153CE6C` 都超過 **15 秒**時，`8F1C30(-1)` 淡回區域音樂 |
| 特殊狀態 | `F0F0C0`、`A06A10` | `byte_153CE76` 時固定索引 **11** |

### 4.6 場景音與語音（`9DFB30`，`0x5DEF30`）

**已驗證：**

- 類型 1：`"s%d"` 名稱 sample，走 `A06820`。
- 類型 2：`sound\scene%d.mp3` 串流，走 `8F30E0`。
- 類型 3：`sound\voice\%s-%c.mp3`。

**待驗證：** `9DFB30` 的資料表來源（`9DF200` 透過 vtable `0x13793B8` 呼叫）。

### 4.7 地圖環境音 `envsound.def`（`8287D0`／`8257D0`／`829FD0`）
